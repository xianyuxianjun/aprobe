# 降级模式与 Agent 模式共享同一条流程与同一套工具接口

Status: accepted

我们同时需要两样东西：一个**不调用任何模型**就能跑通全流程的模式（CI 能在无密钥机器上回归，指标可复现），以及一个**有界自主循环**的 Agent 模式（M1）。决定：**两者是同一条流程的两个 driver**——同一个规划器 seam、同一套注册工具、同一份 Test Case 产物结构；执行、判定、Trace 与报告完全不感知当前用的是哪一种模式。

被否决的替代方案：

- **两条独立管道**（一条确定性、一条 Agent）。最省事的写法，但安全边界与判定逻辑要维护两遍，而且两种模式产出的指标不可比——一旦不可比，降级模式就只剩下"能跑"这一个意义。
- **只做 Agent 模式，没有密钥就直接失败**。会让评估指标的可用性依赖外部服务，CI 回归也就无从谈起。
- **把模型作为确定性流程里的零散增强**（在若干步骤里可选地插入模型调用）。这会让"哪一步用了模型"变得无法回答，直接违背 ADR-0002 对可解释性的要求。

Consequences：

- 评估指标在两种模式下可比，因此"降级模式 vs Agent 模式"的质量差值本身就是一个可展示的量化结果。
- 工具接口必须设计成与传输无关的注册表，这样 ADR-0001 的"生成阶段没有网络出口"在两种模式下同样成立。
- 代价：Agent 模式不能引入"只有模型才能完成"的步骤。任何新能力都必须能被表达为一个已注册工具，否则它就不属于这条流程。
