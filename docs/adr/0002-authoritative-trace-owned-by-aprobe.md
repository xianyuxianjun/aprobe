# 权威轨迹由 aprobe 持久化，编排层状态不是事实来源

Status: accepted

我们使用 LangGraph 承担编排（流转、打断、恢复），但决定：**一次运行的事实来源是本项目自己按固定结构持久化的 Trace**，而不是编排层的 state / checkpointer。编排层的中间状态只用于流转控制，不参与回放、评估与结论推导。

被否决的替代方案：**以框架的 checkpointer 为权威**。它省掉一层 schema，但会让"同一用例集重复回放得到相同结论"变成框架版本的行为而不是本项目的能力；也无法回答"某个结论来自哪一步、消耗了多少预算"。

Consequences：

- Trace 的结构由本项目拥有并版本化，模型名、提示版本、工具调用与预算消耗都必须显式落库。
- 评估指标（判定准确率、无依据结论率、重复回放一致率）建立在自有 Trace 之上，不依赖框架遥测。
- 代价：需要自己维护一层 Trace schema，并在每个节点边界显式写入；这与"用框架省掉自研编排"的目标存在张力。
